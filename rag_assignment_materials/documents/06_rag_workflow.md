# 传统 RAG 与 Agentic RAG

## 传统 RAG

传统的两步 RAG 先检索资料，再生成回答。程序根据问题取出相关片段，把片段拼成 context，并将参考资料和问题一起传给聊天模型。执行顺序由程序确定，每次调用都会经过检索。

如果应用只回答内部资料问题，每次先查资料是一种容易理解和验证的设计。资料加载和建库通常可以提前完成，不需要每个问题都重新读取文件并生成所有文档向量。

## Agentic RAG

Agentic RAG 把检索作为工具，模型根据上下文决定是否使用、使用什么搜索词，以及是否需要再次搜索。它可以处理普通聊天和资料查询混合的场景，但需要检查工具选择是否正确。使用 Agent 并不自动保证答案更准确。

## 回答与引用

提供给模型的参考资料应包含可追溯的文件名或片段编号。回答引用某份资料时，必须核对原文是否支持该说法。对于明确询问“笔记中如何规定”的问题，资料缺失时应说明未找到依据，不应把模型的一般知识当成笔记事实。
