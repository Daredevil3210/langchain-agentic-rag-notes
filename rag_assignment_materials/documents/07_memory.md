# 多轮问答与短期记忆

## 为什么需要对话上下文

用户先问“什么是向量数据库”，再问“它和普通数据库有什么区别”，第二句中的“它”需要结合前文理解。如果每次只把最新一句交给模型，而没有传入历史或恢复会话状态，程序无法保证理解这一指代。

## 两种练习方式

简单的文字问答可以由程序维护消息列表，把先前的问题和回答随新问题一起发送。LangChain Agent 也可以配置 checkpointer，通过 thread_id 区分和恢复会话状态。

使用 InMemorySaver 时，状态保存在内存中，进程退出后不会自动保留。若需要重启后继续会话，可以配置持久化检查点存储。thread_id 用于区分会话，但它本身不是身份认证机制。

## 不要混淆三类数据

知识库保存供检索的学习资料。对话历史保存这一次聊天的上下文。业务数据库可以保存任务、订单等业务记录。这三者的用途不同，增加对话记忆不会自动把聊天内容写进知识库。

reset 应清除当前会话的上下文；在一个设计合理的知识库助手中，重置聊天不应顺便删除原始资料。重新提问时，资料仍应可以被检索。
